# 工作流编排、账号菜单与工作台整合

## 使用方式

1. 打开「工作流编排」，选择流程并进入设计器。
2. 点击节点，在右侧表单配置查询工具、条件、知识库或模型指令；需要直接编辑时展开「高级配置 JSON」。条件节点可直接选择“满足条件”和“不满足条件”的后续节点。
3. 点击「试运行」，在右侧选择场景用例。系统填入业务参数，也可以自行修改。检查项可点击定位到需要修正的节点。
4. 点击「开始运行」。有未保存修改或新建流程时，按钮显示「保存并开始运行」，保存成功后才运行。
5. 查看执行轨迹、每个节点的输入/输出/错误和最终输出。人工节点暂停后，可以同意或拒绝；刷新页面会恢复待处理的运行。

试运行调用真实服务。业务工具只允许只读查询，不会创建工单、退款或变更权限。结束节点返回实际上下文，不以“生成工单”之类的节点名称冒充业务写入。AI 节点需要已配置的服务，知识节点还需要已索引的文档。

## 布局与交互

- 左侧节点库、中间画布、右侧属性/测试面板。试运行不再挤占画布下半部分；进入测试时收起节点库，为流程留出更多空间。
- 画布适应侧栏后的实际可用尺寸，保留缩放与自动布局；条件节点有独立的“满足”和“不满足”连接点。
- 表单按节点自动推导订单号、业务主体编号、判断字段等输入；高级 JSON 默认折叠。
- 运行前检查配置格式、必需节点、连线数量、条件分支、循环、不可达节点、知识库和模型指令。服务端继续执行权限、真实数据和运行状态校验。
- 运行失败保留错误与已完成步骤；事件连接中断时查询服务端记录，不自动重新执行业务操作。
- 桌面支持画布与列表，手机默认列表，测试面板独立占满工作区。`Ctrl/Cmd + S` 保存，`Esc` 收起面板。
- 账号菜单统一头像、身份信息、主题开关和退出按钮；支持外部点击关闭、Esc、方向键、Home/End。
- 原「系统管理」并入工作台的「服务与运行环境」。工作台顶部“运行环境”入口定位到该区域，旧 `/system` 地址跳转到 `/#services`。服务状态注明配置与实际请求结果的区别。

## 内置场景用例

每个场景可在「流程设置」中载入可运行模板，载入后仍需保存。四条原始、未修改的空配置模板会在启动时升级；已修改节点配置、名称、说明或连线的工作流不会被覆盖。运行记录仍使用各自的定义快照。

| 场景 | 测试输入 | 预期路径 |
| --- | --- | --- |
| 电商售后 | `orderNo=ORD-20260918-001` | 查询真实已完成订单 → 满足条件 → 人工确认 → 同意后输出结果 |
| 电商售后 | `orderNo=ORD-20260920-008` | 服务中订单 → 不满足条件 → 返回分流结果 |
| SaaS | `subjectNo=TENANT-2001, severity=高` | 核验租户 → 满足条件 → 人工确认 |
| SaaS | `subjectNo=TENANT-2001, severity=普通` | 核验租户 → 不满足条件 → 返回结果 |
| IT 服务 | `subjectNo=EMP-3108, category=权限` | 核验员工 → 满足条件 → 人工审批 |
| IT 服务 | `subjectNo=EMP-3108, category=网络` | 核验员工 → 不满足条件 → 返回结果 |
| 商家申诉 | `subjectNo=MER-8802, materialsComplete=true` | 核验商家 → 材料齐全 → 人工复核 |
| 商家申诉 | `subjectNo=MER-8802, materialsComplete=false` | 核验商家 → 材料不足 → 返回分流结果 |
| 知识检索 | `question=退款申请有哪些条件？`，选择售后知识库 | 返回真实文档片段与命中数量；没有命中时返回空证据 |
| 通用助手 | `question=员工办公网络无法连接，请用三句话说明排查步骤。` | 调用模型 → 返回实际生成内容 |

种子编号用于本项目内置数据。若当前数据库已修改或清理种子记录，需要换成当前账号有权限访问的业务编号。页面的“符合用例预期”检查运行状态和所走分支，不评判模型回答的业务准确性。

## 自动测试

在项目根目录执行：

```powershell
npm --prefix ai-chatbot-web test
npm --prefix ai-chatbot-web run build
mvn -f ai-chatbot-service/pom.xml test
python scripts/test-workflows.py --base-url http://127.0.0.1:15175 --env-file .env.docker --with-ai
```

后端涉及相对测试存储路径时，也可进入 `ai-chatbot-service` 后执行 `mvn test`。最后一条命令需要 Docker 服务已启动，它通过现有管理员配置登录，在隔离的临时工作流上执行用例，结束后只清理本次创建的工作流，不修改已有流程。凭据不会输出到日志。`--with-ai` 会调用真实知识检索和模型服务；不传该选项时只验证业务场景与缺少知识库的失败路径。未配置 AI 或没有已索引文档会明确报告跳过原因。

测试代码：

- `ai-chatbot-web/tests/workflow-designer.test.mjs`：输入推导、必填校验、布尔与嵌套字段、JSON 错误、非法字段、分支、循环、不可达节点、用例结果断言。
- `ai-chatbot-web/tests/api-stream.test.mjs`：流式事件、断流、错误、运行编号与运行记录查询。
- `ai-chatbot-web/tests/ai-status.test.mjs`：服务状态展示与旧系统页面跳转。
- `WorkflowScenariosIntegrationTest`：真实执行器与 H2/MySQL 兼容数据库，四种业务场景双分支、审批通过/拒绝、持久化恢复、无业务写入、缺少输入和知识库、模板升级保护。
- `WorkflowNodeExecutorTest`：工具授权、条件结果、知识证据/空结果、外部调用超时、模型响应/空响应/未启用。
- `scripts/test-workflows.py`：Docker 实例上的 MySQL 数据与 API 验收，包括真实向量检索和模型调用。

### 页面手工验收

| 操作 | 预期 |
| --- | --- |
| 新建流程，填写测试问题，直接开始 | 自动保存后运行，按钮不会永久禁用 |
| 修改已保存节点，再试运行 | 提示保存并运行，执行最新已保存定义 |
| 留空必填订单号 | 在面板内提示，不发起运行 |
| 删除条件的一条分支 | 运行前列出具体节点问题，可以跳转修正 |
| 展开知识节点 | 下拉选择知识库，不必手填 ID |
| 审批等待中刷新 | 恢复同一运行的确认按钮 |
| 审批拒绝 | 停止后续节点，显示人工拒绝原因 |
| 运行完成后重新测试 | 回到输入表单，保留当前页面内的输入 |
| 查看某个节点 | 画布选中该节点，测试面板展开输入与输出 |
| 390×844 窄屏 | 输入、检查结果、开始按钮可见，没有横向溢出 |
| 账户菜单切换深色后按 Esc | 主题生效，菜单关闭，焦点返回账户按钮 |
| 打开 `/system` | 跳转到工作台运行环境区域，无单独系统管理导航 |

## Docker 发布

本机已有 MySQL 恢复配置，需要沿用两份 Compose 文件。仅重建应用服务：

```powershell
docker compose --env-file .env.docker -f compose.yaml -f .env.recovery.compose.yaml build backend web
docker compose --env-file .env.docker -f compose.yaml -f .env.recovery.compose.yaml up -d --no-deps backend web
docker compose --env-file .env.docker -f compose.yaml -f .env.recovery.compose.yaml ps
```

新环境参考 README，使用 `.env.docker.example` 配置凭据，只使用 `compose.yaml` 完整启动 MySQL、后端和 Web。

- 页面：`http://127.0.0.1:15175`
- 后端：`http://127.0.0.1:18082`
- 本次不重建 MySQL，也不删除任何现有数据卷。
