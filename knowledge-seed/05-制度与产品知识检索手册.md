# 一、制度与产品知识检索的适用范围

“制度与产品知识检索”帮助员工和客服查找产品手册、服务政策、操作流程及公告，并依据命中的文档片段回答问题。此场景不配置业务工具，适合知识查询，不执行订单变更、权限开通、退款或工单创建。

本手册提供企业智能服务中心的产品功能说明和知识维护建议。仓库没有提供某家企业正式批准的考勤、请假、差旅报销、采购额度、审批人名单或客户合同，因此不能从本手册推导这些企业制度的具体条款。询问报销上限、年假天数、产品定价、订阅配额或赔付标准时，应先补充适用企业的正式制度、合同或产品版本资料，再依据原文回答。

# 二、如何开始一次带知识引用的产品问答

在会话中心先选择业务场景“制度与产品知识检索”，再在“知识范围”选择“制度与产品知识检索手册”，然后发起新对话。业务场景和知识范围是两个独立选项；只选业务场景不会自动绑定知识库。未选知识库时按普通聊天处理，不能把普通回答当作已引用企业资料的结论。

选择知识库后，系统先检索该知识库的相关片段，再结合检索结果回答。生成完成后可查看知识引用及链路追溯，复核引用文档、命中的内容和回答依据。已有会话应核对其知识范围，避免误用其他业务领域的资料。

可用于验证本知识库的问题：

- 知识中心支持上传哪些文件格式？
- 文档显示 PENDING_AI 时应该怎么办？
- 修改知识库名称后是否需要重新索引？
- 只选择“制度与产品知识检索”场景会自动使用知识库吗？
- 遇到两份生效时间不同的制度应该如何核对？
- 知识不足时应补充哪些资料？

# 三、知识中心的产品功能

知识中心支持创建知识库、编辑名称和描述、上传 PDF、TXT、Markdown 文件，以及查看文档原文、分词片段和索引状态。不同业务线或适用范围的资料建议分库维护；分库便于选择检索范围，但不能单凭分库名称认定已完成组织权限配置。

修改知识库的名称和描述不会删除已上传文档，也不需要重新索引。文档内容发生变化时，应更新资料并重新索引；重新索引读取当前存储的文件，不会自动下载外部网站或同步其他系统中的最新版制度。

知识库内容不会自动把业务查询权限授予用户。业务工具受当前账号与场景配置约束，有业务副作用的动作需经过系统独立的确认流程。检索手册中的流程说明也不代表已经执行了审批或业务变更。

# 四、文档索引状态与处理流程

上传资料后，文档会进入异步索引流程，读取正文、切分片段并写入向量索引。只有索引完成的资料才能用于正常知识检索。

- UPLOADED：文档已登记，等待索引处理。
- INDEXING：系统正在解析文件、切分正文并建立索引。
- READY：文档已完成索引，可用于知识问答；可在知识中心核对原文和片段。
- PENDING_AI：当前环境未启用 AI 或向量服务不可用。需在对应运行环境启用并配置 AI 服务，再重新索引；不能仅通过刷新聊天页面解决。
- FAILED：索引失败。先查看文档错误提示，核对文件是否包含可提取的正文、模型服务是否可用，再重试索引。

系统中的 AI“参数已配置”表示相关配置已填写，不能替代实际请求验证。扫描图片型 PDF 如果没有可提取的文本，需先获得文字内容再导入；不能把上传成功等同于已成功索引。

# 五、制度资料与产品手册的维护建议

新增正式资料时，建议在正文中写明标题、文档编号、责任部门、适用对象、产品或制度版本、发布日期、生效日期、失效日期、替代文件及权威原文入口。这些是维护建议，本产品当前不会自动验证审批盖章或制度法律效力。

制度资料建议包括：适用对象与业务范围、办理条件、材料清单、办理步骤、审批角色、例外处理、咨询渠道。金额、时限和人员名单应使用本企业批准的真实条款，不应直接套用演示值。

产品资料建议包括：适用版本、功能范围、前置条件、操作入口、完整操作步骤、常见错误、限制及升级支持渠道。定价、额度、服务承诺和支持时段应引用正式产品说明或客户合同，没有资料时不得承诺。

公告建议说明：影响对象、变更内容、生效时间、旧流程的过渡安排、用户需执行的动作和反馈渠道。紧急公告也需要明确来源和发布主体，不能仅凭标题包含“最新”判断其有效性。

# 六、如何核对制度版本和冲突

回答制度问题前，应核对文件的适用组织、岗位、地区、产品版本及生效时间。发布日期、上传时间和生效日期含义不同；上传时间较晚不代表制度已经生效，未来生效的版本也不能直接替代当前版本。

当两份资料冲突时，应分别列出文档标题、版本、生效日期和冲突条款，检查是否存在明确的替代说明及适用范围差异。仍不能判断时，请制度责任部门或产品负责人确认；不要把互相冲突的规则拼接成一个结论。

过期文档可能仍用于历史问题核对。维护人员应明确标注其有效期并检查当前知识库是否混入已失效资料。产品不会仅根据正文中的日期自动完成版本淘汰或权限审批，回答者需要复核引用。

# 七、没有检索依据时如何处理

知识不足时应明确说明尚未找到适用依据，并列出需要补充的文件或字段。例如，询问“出差住宿能报销多少”时，需要对应企业、员工类别、目的地及生效中的差旅制度；本手册未提供住宿限额，不能猜测一个金额。

如果文档已 READY 但未命中，应依次核对知识范围、文档内容、问题中的产品名称或制度关键词，以及问题的适用版本。可尝试使用原文中的术语重新提问，必要时请知识管理员补充完整条款与上下文。

可复核的答复应说明结论、适用条件、相关步骤及引用依据。无法确认的部分应单独说明，敏感信息应通过受控渠道提供；密码、验证码、访问令牌和私钥不应录入知识正文或聊天。

# 八、典型问答

问：修改知识库名称后，原有资料会丢失吗？
答：不会。编辑知识库名称和描述不会删除原有文档，也不需要重新索引。只有资料内容发生变化时才需要重新处理。

问：选择了知识检索场景，为什么回答没有知识引用？
答：先检查是否同时选择了知识范围，再检查对应文档是否已 READY。业务场景不会自动绑定知识库，未选择知识库的对话按普通聊天处理。若仍没有引用，应复核检索是否命中相关资料。

问：产品是否可以直接替我批准请假或报销？
答：此场景仅进行知识检索，没有配置执行此类审批的业务工具。本手册也未提供企业请假或报销制度，需要依据企业正式流程办理。

问：后上传的制度是否一定优先？
答：不一定。应核对适用范围、生效日期和明确的替代说明。上传时间不能作为判断制度效力的唯一依据。
