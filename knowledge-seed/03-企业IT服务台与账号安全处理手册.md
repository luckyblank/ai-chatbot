# 一、身份与权限请求的基本原则

服务台处理账号、密码和权限问题时，应先验证申请人身份，再执行任何能够改变访问权限的操作。聊天中不得要求用户提供密码、短信验证码、MFA 动态码、恢复密钥或管理员令牌。

身份验证应采用组织批准的方式，例如已登记设备确认、工号与内部流程组合验证、主管审批或身份系统的受控校验。仅凭用户自报姓名、邮箱或截图不足以完成高风险重置。

# 二、密码重置流程

1. 确认账号标识和受影响系统；
2. 判断是忘记密码、账号锁定、MFA 失败还是疑似被盗；
3. 使用批准的身份验证流程；
4. 检查是否存在异常登录、联系方式被修改或连续失败记录；
5. 普通遗忘问题可引导自助重置；
6. 疑似账号被盗时，应升级安全事件，必要时撤销现有会话、重置凭据并检查影响；
7. 操作完成后提醒用户使用独立的长密码、密码管理器和 MFA。

任何重置、解锁或 MFA 解绑都属于写操作。智能客服只能在展示拟执行动作并获得明确确认后调用相应工具；高权限账号应转人工审批。

# 三、权限申请和离职变更

权限分配遵循最小必要原则，只授予完成当前工作所需的范围和期限。客服需要确认资源名称、角色、业务理由、申请期限、审批人和紧急程度。

管理员、财务、生产环境和批量数据访问属于高风险权限，不能仅依赖聊天确认。临时权限应设置到期时间。人员离职、岗位变更或外包结束时，应按组织流程及时回收访问权限并保留审计记录。

# 四、钓鱼与可疑消息处理

常见信号包括：催促立即操作、要求提供凭据或验证码、域名异常、附件来源不明、付款账户突然变更、制造恐慌或提供过度诱人的奖励。

客服建议应是：不要点击可疑链接或打开附件；不要回复敏感信息；通过组织批准渠道报告给安全团队；如果已经输入凭据，应立即从可信设备修改密码、撤销会话并检查 MFA；如果已经运行附件，应断开风险设备并联系安全团队。

不得让用户把可疑附件再次上传到普通客服聊天中，以免扩大传播。应使用隔离的安全分析渠道。

# 五、安全事件升级信息

升级时记录：发现时间、受影响账号和设备、可疑消息来源、用户已执行动作、是否输入凭据、是否发生异常登录或数据访问、当前隔离状态。不要在普通工单中保存敏感令牌或完整个人数据。

事件响应应覆盖准备、检测、响应、恢复和后续改进。服务台负责快速识别和准确升级，安全团队负责调查、遏制、清除和恢复。

# 六、用户回复模板

“为了保护账号安全，请不要发送密码、验证码或恢复密钥。我会先确认问题类型并引导您通过组织批准的身份验证流程。若存在异常登录迹象，将立即升级安全团队处理。”
