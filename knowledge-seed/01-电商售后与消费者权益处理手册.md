# 一、客服处理目标

处理电商售后问题时，客服应同时完成四件事：确认消费者诉求、核实订单事实、判断适用规则、给出可执行的下一步。不得在订单、物流、支付状态尚未核实时承诺退款到账时间或认定责任方。

# 二、受理时的最小信息集

优先收集：订单号、商品名称、签收时间、问题类型、期望方案。仅在确有必要时收集联系方式、退货地址或问题图片。不要在对话中索要完整身份证号、银行卡密码、短信验证码或支付密码。

建议问题分类：

1. 未发货取消；
2. 物流停滞、丢失或破损；
3. 七日无理由退货；
4. 质量问题退换修；
5. 少件、错发或描述不符；
6. 退款到账查询；
7. 高风险投诉、欺诈或人身财产安全问题。

# 三、七日无理由退货判断

网络销售通常应先判断消费者是否处于签收后的七日窗口，再判断商品是否属于法定例外或已经由消费者在购买时明确确认不适用无理由退货。

常见法定例外包括消费者定制商品、鲜活易腐商品、已拆封的部分数字化商品以及交付的报纸期刊。对于其他基于商品性质不适宜退货的商品，不能仅依靠平台默认勾选排除退货；应有显著提示和消费者主动确认记录。

消费者为检查商品进行合理拆封或调试，只要没有影响商品原有品质、功能和外观，不应机械地以“已拆封”为由拒绝。最终是否满足完好标准，应结合商品属性、配件、赠品和使用痕迹核实。

消费者依据无理由退货规则退货时，通常由消费者承担退回运费；企业政策或双方另有约定的，按约定处理。经营者收到退回商品后，应依法及时返还商品价款。

# 四、质量问题与履约异常

商品或服务不符合质量要求时，应优先依据法律规定、商品三包规则和双方约定判断退货、更换或修理方案。不能把本应由经营者承担的必要运输费用转嫁给消费者。

物流破损处理建议：先确认外包装、商品本体、签收方式和举证材料；对可能扩大损失的情形，先提供拒收、妥善保管或停止使用建议，再启动物流核查。涉及人身或财产安全的商品，应立即升级人工和风险团队。

退款状态必须区分：商家尚未审核、平台处理中、支付渠道处理中、已原路退回。客服只能基于系统状态说明进度，不能把“已提交退款”表述成“资金已经到账”。

# 五、标准处理链路

1. 复述诉求并确认优先级；
2. 使用订单工具核实商品、付款、发货、签收和售后状态；
3. 使用售后资格工具判断时限、品类和当前可选方案；
4. 给出方案、预计节点和需要用户完成的动作；
5. 需要创建工单、退款或补偿时，先展示拟执行内容并获得明确确认；
6. 记录处理结果、证据和承诺，避免用户重复说明；
7. 超权限、重大投诉或疑似违法风险，升级人工处理。

# 六、回复口径示例

可用表达：“我已经核实到订单当前为已签收，接下来会结合签收时间和商品类型确认可用的退货方案。为避免误判，我不会在系统校验完成前承诺退款结果。”

不建议表达：“肯定能退”“马上到账”“物流一定丢了”“这不归平台管”。
