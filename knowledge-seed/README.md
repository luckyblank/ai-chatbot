# 企业客服知识库种子资料

本目录保存 RAG 种子文档：前四份依据权威公开资料整理，第五份依据本项目的产品实现和业务使用指南整理。正文是面向实际工作的中文说明，不是对来源网页的逐字复制。

- `01-电商售后与消费者权益处理手册.md`：对应电商售后服务。
- `02-SaaS故障响应与客户沟通手册.md`：对应 SaaS 客户成功与故障升级。
- `03-企业IT服务台与账号安全处理手册.md`：对应企业 IT 服务台。
- `04-平台商家治理与申诉处理手册.md`：对应平台商家运营。
- `05-制度与产品知识检索手册.md`：对应制度与产品知识检索，包含产品功能、知识导入与索引、制度版本核验建议和典型问答；不包含未提供的企业正式制度。

每份文件都包含适用范围、版本日期、风险边界和来源。生产使用时，应继续加入企业自己的合同、SLA、退换货政策、平台规则和内部审批流程；企业内部规则与公开资料冲突时，应由法务和业务负责人确认最终口径。

## 导入与使用

后端启动时会将尚未登记的 `两位数字-标题.md` 文件增量加入知识中心，包括已存在知识目录的环境。每个文件对应一个知识库，导入历史持久化在 `knowledge-catalog.json`，重复启动不会重复创建，也不会覆盖用户修改的名称、描述及已有索引。用户删除已登记的内置文档或知识库后，重启不会自动恢复；升级旧目录时同样保留前四份历史手册的删除状态。

新增文档随后进入已有的启动索引流程。启用并配置 AI 服务后应达到 `READY`；未启用 AI 时显示 `PENDING_AI`，需要配置后重新索引。更新已登记文件的正文后，需在知识中心手动重新索引。

使用第五个知识域时，在会话中心分别选择业务场景“制度与产品知识检索”和知识范围“制度与产品知识检索手册”。可用“知识中心支持上传哪些文件格式？”、“文档显示 PENDING_AI 时应该怎么办？”验证检索及引用。业务场景不会自动绑定知识库；通用智能助手本身不要求内置知识库。
